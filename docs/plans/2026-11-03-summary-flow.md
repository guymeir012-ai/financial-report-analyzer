# תוכנית: שלב 13, משימה 3 (הזרימה הראשונה: בית, אישור, עמוד סיכום)
תכנון: Opus 5.5. ביצוע: Sonnet 5.5. ענף: claude/peaceful-dijkstra-zw3bro (לא main).

## מטרה
דנה מקלידה סימול, רואה את שם החברה ואת הדוח האחרון עם התאריך, מאשרת, ומקבלת טבלת יחסים: תקופה נוכחית, תקופה קודמת, שינוי. לחיצה על כל מספר מציגה את המקור שלו (תגית XBRL, דוח, תקופה, קישור ל-SEC). המנוע הקיים (`backend/ratios.py`, `analyze`) לא משתנה, רק נצרך.

## מחוץ לתחום
תמחור ומכפיל רווח, חדשות, שאלות, כניסה עם סיסמה, ניתוחים אחרונים (דורש Supabase), שורת התקדמות. אין המלצות קנייה או מכירה בשום מקום.

## דפים (Flask, תבניות Jinja ב-`frontend/templates`, CSS ב-`frontend/static`)
1. `GET /` בית: שדה סימול אחד (טופס GET אל `/confirm`), דוגמאות לחיצות (NVDA, AAPL, MSFT).
   1. סימול לא תקין: הבית מוצג שוב עם הודעה בעברית, קוד 400.
   2. סימול שלא נמצא: הבית מוצג עם "האם התכוונת ל:" וקישורים לסימולים הקרובים (`TickerNotFound.suggestions`), קוד 404.
   3. שדה ריק: הבית עם הודעה "יש להזין סימול", קוד 400.
2. `GET /confirm?ticker=X` אישור: שם החברה, סימול, CIK, הדוח האחרון (סוג, תאריך הגשה, סוף התקופה), קישור לדוח ב-SEC. כפתור "אישור, נתח" אל `/summary/X`, וכפתור "לא החברה הנכונה" אל `/`. חברה בלי 10-Q/10-K: הודעה, קוד 404.
3. `GET /summary/<ticker>` סיכום: ראש עמוד (חברה, סימול, סוג הדוח, סוף התקופה, תאריך הגשה, קישור), הודעת `notice_he` אם יש, ואז טבלת יחסים.
   1. עמודות: יחס, תקופה נוכחית, תקופה קודמת, שינוי. כותרות העמודות כוללות את סוג הדוח וסוף התקופה.
   2. ערך: אחוז עם ספרה אחת אחרי הנקודה (יחסי צמיחה ורווחיות, ROE, הון למאזן), או מכפיל עם שתי ספרות ו-x (יחס שוטף, חוב להון).
   3. סטטוס שאינו ok: מוצג `status_he` (לא דווח, לא ניתן לחישוב: ..., לא רלוונטי לבנקים). אף פעם לא מספר מנוחש.
   4. שינוי: באחוזים, נקודות אחוז (pp); במכפיל, הפרש. רק אם שני הערכים ok, אחרת "—".
   5. צבע וחץ לפי טובה/רעה (כמו ב-Stitch): ירוק ▲ לשינוי לטובה, אדום ▼ לרעה, אפור ללא שינוי. הסימן (+/-) מראה את כיוון המספר. חוב להון: ירידה = לטובה. כל השאר: עלייה = לטובה.
   6. מקור: כל מספר הוא `<details>`; לחיצה פותחת חלונית עם הנוסחה ולכל רכיב: שם בעברית, תגית XBRL, ערך (מיליוני דולר), תקופה (start עד end), סוג דוח, מספר accession, תאריך הגשה, קישור לדוח. ב"לא דווח" החלונית מציגה מה חסר. בלי JavaScript.
4. שגיאות בדפים (לא ב-`/api/`): דף שגיאה HTML בעברית, בלי פרטים פנימיים. SEC לא זמין: 502 "לא זמין כרגע". שגיאת הגדרות או חריגה: 500 כללי. נתיבי `/api/` ממשיכים להחזיר JSON כמו היום.

## שמירה מקומית (cache) לתשובות EDGAR (אפיון, "מקורות מחירים" סעיף 3)
1. ב-`SecClient`: פרמטר `cache_dir` (ברירת מחדל None = כבוי, כך שהבדיקות הקיימות לא משתנות). האפליקציה יוצרת לקוח עם `get_sec_cache_dir()` מ-`config.py`: משתנה `SEC_CACHE_DIR`, ברירת מחדל `<repo>/.cache/sec` (ב-`.gitignore`).
2. מפתח: sha256 של ה-URL, קובץ `<hash>.json` שמכיל `{"url", "fetched_at", "data"}`. שם הקובץ לא נגזר מקלט המשתמש, אין path traversal.
3. תוקף: רשימת הסימולים 24 שעות, submissions ו-companyfacts 6 שעות (דוח חדש מופיע תוך זמן סביר).
4. כתיבה אטומית (קובץ זמני ו-`os.replace`), תיקייה בהרשאות 0700. קובץ פגום או URL שלא תואם: מתעלמים ומושכים מחדש.
5. SEC לא זמין (שגיאה זמנית, לא 404) ויש עותק ישן: מחזירים את הישן ורושמים בלוג. אין עותק: השגיאה הרגילה.
6. רק תשובות 200 תקינות נשמרות.

## אבטחה
1. Jinja autoescape, ולידציה לסימול דרך `normalize_ticker` הקיים.
2. כותרות לכל תשובה: `Content-Security-Policy` (default-src 'self'; style-src 'self' fonts.googleapis.com; font-src fonts.gstatic.com; script-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
3. קישורים חיצוניים רק ל-`https://www.sec.gov/`, עם `rel="noopener noreferrer"`.
4. אין מפתחות בקוד, אין debug, דפי שגיאה בלי traceback.
